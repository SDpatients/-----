## 一、inspection_standard（检验标准表）⚠️ 当前报错的表

| 状态 | Java 字段 | DB 列 | 说明 |
|------|-----------|-------|------|
| ✅ | standardNo | standard_no | 匹配 |
| ✅ | materialCode | material_code | 匹配 |
| ✅ | materialName | material_name | 匹配 |
| ✅ | standardName | standard_name | 匹配 |
| ✅ | sampleRule | sample_rule | 匹配 |
| ✅ | versionNo | version_no | 匹配 |
| ✅ | inspectionStrategy | inspection_strategy | 匹配 |
| ✅ | sampleRate | sample_rate | 匹配 |
| ✅ | status | status | 匹配 |
| ✅ | remark | remark | 匹配 |
| 🔴 | **acceptanceRate** | ~~acceptance_rate~~ | **Java 有此字段，DB 无此列 ← 当前报错原因！** |

**报错 SQL：**
```sql
SELECT ..., sample_rate, acceptance_rate, status, ... 
FROM inspection_standard 
WHERE deleted=0
```
**修复方案：** 在 DB 中添加 `acceptance_rate` 列：
```sql
ALTER TABLE inspection_standard
    ADD COLUMN acceptance_rate DECIMAL(5, 2) DEFAULT NULL COMMENT '合格标准率'
    AFTER sample_rate;
```

## 七、⚠️ appeal（申诉表 Entity）— 有 Entity 但数据库无对应表

| Entity 类 | @TableName | 数据库表 |
|-----------|------------|----------|
| `Appeal.java` | `appeal` | ❌ 不存在 |

**说明：** `Appeal` 和 `QualityAppeal` 功能有重叠（都有 `appealNo`, `ncrId`, `inspectionId`, `supplierId`, `appealReason`, `appealStatus`），但 `Appeal` 多了 `deductionId`, `appealDesc`, `adjustAmount`, `reviewer`, `reviewerName`, `reviewTime`, `reviewOpinion` 等字段。

**修复方案（二选一）：**
- **合并**：将 `Appeal` 的独有字段合并到 `QualityAppeal` 及 `quality_appeal` 表，删除 `Appeal.java`
- **建表**：为 `Appeal` 创建独立的 `appeal` 表
