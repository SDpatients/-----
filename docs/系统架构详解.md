# 供应商协同系统架构详解

## 1. 文档定位

本文档基于项目根目录 README、现有后端结构、数据库脚本与 Docker 部署配置，对供应商协同系统进行更细粒度的架构说明。系统目标是打通采购方与供应方之间的业务、数据、消息与文件协同链路，形成覆盖寻源、订单、交付、质量、结算、门户、权限与集成的 SRM 平台。

## 2. 架构目标

### 2.1 业务目标

| 目标 | 说明 |
|---|---|
| 采购流程线上化 | 将 RFQ、订单下发、交期反馈、ASN、质检、对账、发票等流程线上闭环 |
| 供应商自助协同 | 供应商可通过门户完成报价、接单、发货、异常处理、对账确认、申诉等操作 |
| 内外角色隔离 | 采购方内部用户与供应商外部用户通过权限体系、数据范围与门户能力隔离 |
| 业务过程可追溯 | 关键单据、状态变更、审批动作、消息投递、附件上传均需形成审计轨迹 |
| 集成友好 | 支持与 ERP、财务系统、WMS、MES、EDI、企业微信、短信、邮件等系统对接 |

### 2.2 技术目标

| 目标 | 说明 |
|---|---|
| 前后端分离 | 前端 Vue 3 + Element Plus，后端 Spring Boot 3 提供 REST API |
| 统一认证授权 | Spring Security + JWT + RBAC，支持多角色、多门户、多租户扩展 |
| 数据分层存储 | MySQL 存核心交易数据，Redis 存缓存与会话，MongoDB 存日志与非结构化数据，MinIO 存文件，Elasticsearch 存检索索引 |
| 异步解耦 | RabbitMQ 承载订单下发、状态回传、通知、索引同步等异步任务 |
| 容器化部署 | Docker Compose 管理基础设施，生产环境可演进到 Kubernetes |

## 4. 分层职责

### 4.1 用户访问层

采购方管理后台面向采购、质量、仓储、财务、系统管理员等内部角色，强调业务管控、审批、看板与异常处理。供应商门户面向外部供应商用户，强调自助操作、单据响应、进度查看、附件上传与协同沟通。

### 4.2 接入与网关层

接入层负责统一入口、协议终止、静态资源代理、API 路由、跨域控制、访问日志、限流、防刷、灰度发布与前置鉴权。生产环境建议由 Nginx 或云负载均衡承接公网流量，再转发到网关或后端服务。

### 4.3 应用服务层

应用服务层以 Spring Boot 单体模块化方式起步，按业务域拆包。随着规模增长，可将订单、质量、结算、门户、集成网关拆分为独立服务。当前项目包结构已包含 common 与 security 基础能力，后续业务模块建议继续沿用 `com.supplier.{domain}` 的包边界。

### 4.4 数据与中间件层

MySQL 保存强一致、可事务化的业务主数据与单据数据；Redis 保存短生命周期数据、令牌黑名单、字典缓存、分布式锁与热点统计；RabbitMQ 承接异步事件；MongoDB 保存操作日志、消息内容、8D 附件描述、接口报文快照等非结构化内容；MinIO 保存证书、合同、图纸、发票、报告附件；Elasticsearch 提供供应商、物料、订单、异常单据的全文检索。

## 7. 核心业务流

### 7.1 供应商准入流程

```text
供应商注册 → 填写企业信息 → 上传资质证书 → 采购方初审 → 质量/财务复审 → 准入通过 → 创建供应商账号 → 分配角色权限
```

关键控制点：统一社会信用代码唯一、资质有效期校验、黑名单校验、联系人手机号校验、审核日志留痕、准入状态不可跳跃。

### 7.2 RFQ 询价流程

```text
采购创建 RFQ → 选择物料与供应商 → 发布询价 → 供应商报价 → 截止报价 → 自动比价 → 议价 → 定价 → 生成采购协议或订单
```

关键控制点：报价截止后不可修改、报价含税/未税口径统一、币种汇率锁定、附件版本留痕、定价结果可追溯。

### 7.3 采购订单协同流程

```text
ERP 订单同步 → 平台生成订单 → 通知供应商 → 供应商接单/拒单 → 反馈交期 → 采购确认 → 交付跟踪 → 订单关闭
```

关键控制点：订单号唯一、订单明细数量不可超收、订单变更必须生成版本记录、供应商只能访问自身订单、关键状态变更发送消息。

### 7.4 ASN 与收货流程

```text
供应商选择订单明细 → 创建 ASN → 填写批次/箱数/数量 → 打印送货单和标签 → 仓库扫码收货 → 生成收货记录 → 触发质检或入库
```

关键控制点：ASN 数量不得超过可发数量、条码唯一、实收差异需记录原因、收货后不可随意修改 ASN，可通过冲销或调整单处理。

### 7.5 质量异常流程

```text
收货触发检验 → IQC 判定不合格 → 创建 NCR → 通知供应商 → 供应商提交原因与措施 → 采购/质量审核 → 8D 整改 → 验证关闭
```

关键控制点：不合格数量与收货记录一致、NCR 处理方式明确、8D 阶段节点可追踪、逾期自动预警、质量扣款进入结算。

### 7.6 财务对账流程

```text
按周期汇总收货/退货/扣款 → 生成对账单 → 供应商确认 → 开票 → OCR 识别与验真 → 三单匹配 → 付款计划 → 付款回传
```

关键控制点：对账单冻结后明细不可修改、发票金额不得超过可开票金额、付款状态以资金系统回传为准、异常差异需人工确认。

## 8. 数据架构

### 8.1 MySQL 数据域

| 数据域 | 代表表 | 说明 |

| 系统管理 | sys_user、sys_role、sys_permission、sys_dict | 用户、角色、权限、字典等基础数据 |

| 财务结算 | reconciliation、reconciliation_detail、invoice、payment | 对账、发票、付款 |

### 8.2 Redis 数据域

| Key 模式 | 用途 | 建议 TTL |
|---|---|---|
| `auth:token:{jti}` | 登录令牌或令牌黑名单 | 与 JWT 过期时间一致 |
| `auth:user:{userId}` | 当前用户权限与角色缓存 | 30 分钟至 2 小时 |
| `dict:{dictCode}` | 字典项缓存 | 1 天或变更时删除 |
| `lock:{business}:{id}` | 分布式锁 | 10 秒至 5 分钟 |
| `rate:{api}:{userId}` | 接口限流计数 | 1 分钟 |
| `todo:count:{userId}` | 待办数量缓存 | 1 至 5 分钟 |

## 9. 权限与数据隔离架构

| 角色类型 | 示例角色 | 数据范围 |

|---|---|
| 菜单权限 | 订单管理、发货管理、质量异常、财务对账 |
| 按钮权限 | 新增、编辑、删除、提交、审核、导出、打印 |
| 接口权限 | `/api/v1/orders/**`、`/api/v1/suppliers/**` |
| 数据权限 | 本人、本部门、本组织、本供应商、指定品类、指定工厂 |
| 字段权限 | 银行账号、税号、发票信息、合同金额等敏感字段脱敏 |

### 9.3 供应商隔离原则

供应商用户登录后必须绑定 `supplier_id`，所有供应商门户查询、详情、下载、提交接口都必须强制追加 `supplier_id = 当前用户供应商ID` 条件。禁止前端传入供应商 ID 后由后端直接信任，后端应以用户上下文为准。

## 10. 消息与通知架构

### 10.1 事件驱动原则

关键业务动作应先完成本地事务，再发布领域事件。消费端负责通知、索引同步、外部系统回传等副作用。消息消费必须支持幂等、重试、死信队列与人工补偿。

### 10.2 通知触发点

| 业务事件 | 通知对象 | 通道 |
|---|---|---|
| RFQ 发布 | 被邀请供应商报价员 | 站内信、邮件 |
| 订单下发 | 供应商管理员、订单员 | 站内信、企微、邮件 |
| 订单即将逾期 | 采购员、供应商订单员 | 站内信、短信 |
| ASN 创建 | 仓库员、采购员 | 站内信 |
| NCR 创建 | 供应商质量员、采购质量工程师 | 站内信、邮件 |
| 对账单发布 | 供应商财务员 | 站内信、邮件 |

## 11. 集成架构

### 11.1 集成模式

| 模式 | 适用场景 | 优点 | 风险控制 |
|---|---|---|---|
| REST API | 实时查询、状态回传、审批触发 | 实时性好、易治理 | 需要鉴权、限流、超时与重试 |
| 消息队列 | 订单下发、收货回传、通知分发 | 解耦、削峰 | 需要幂等、死信与补偿 |
| 文件交换 | 大批量主数据、历史数据迁移 | 简单稳定 | 需要校验、对账与断点续传 |
| 数据库中间表 | 老 ERP、低改造系统 | 兼容性好 | 禁止直接操作核心业务表 |
| EDI | 大型客户或跨企业标准报文 | 标准化 | 需要报文映射与错误回执 |

### 11.2 ERP 同步边界

| 数据 | 主数据来源 | 平台职责 |
|---|---|---|
| 供应商主数据 | ERP 或 SRM，按企业策略确定 | 维护准入、资质、绩效，必要时回写 ERP |
| 物料主数据 | ERP | 只读同步，用于订单、询价、质检 |
| 采购订单 | ERP | 接收订单，协同确认、交期、发货与变更 |
| 收货记录 | WMS 或 SRM | 记录收货结果，回传 ERP |
| 发票与付款 | 财务系统 | 上传发票、对账确认、接收付款状态 |

## 14. 高可用与容灾

| 组件 | 高可用策略 | 容灾策略 |
|---|---|---|
| 后端服务 | 多实例无状态部署 | 镜像回滚、蓝绿发布 |
| MySQL | 主从复制、读写分离 | 定时全量备份 + Binlog 增量恢复 |
| Redis | Sentinel 或 Cluster | RDB + AOF，关键缓存可重建 |
| RabbitMQ | 镜像队列或仲裁队列 | 消息持久化、死信队列 |
| MongoDB | Replica Set | 定时备份、oplog 恢复 |
| MinIO | 分布式纠删码 | 跨节点副本、定期校验 |
| Elasticsearch | 多节点分片副本 | 快照备份、索引重建机制 |

## 15. 演进路线

### 15.1 第一阶段：模块化单体

建立完整业务闭环，统一权限、统一响应、统一异常、统一审计。所有模块在同一后端应用中运行，降低开发与部署复杂度。

### 15.2 第二阶段：领域服务拆分

当订单、质量、结算、门户、集成网关的开发团队或性能瓶颈明显时，将其拆分为独立服务。拆分前必须先完成领域边界、数据库边界、事件契约与接口契约治理。

### 15.3 第三阶段：平台化与生态集成

支持多租户、插件化集成、低代码流程配置、可配置表单、统一消息中心、供应商绩效模型、智能预警与数据分析。
