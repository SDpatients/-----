# 供应商协同系统前端参考总指导方案

## 1. 文档定位

本文档基于 `architecture-detail.md` 与 `rules-and-standards.md` 制定，用于指导供应商协同系统前端工程的总体设计、目录组织、页面开发、接口对接、权限控制、状态字典、组件抽象、数据安全、测试验收与持续演进。所有采购方管理后台、供应商门户、系统管理页面以及后续扩展模块，均应遵循本文档，以保证前端实现风格统一、业务交互一致、权限边界清晰、接口协作稳定。

本文档重点回答以下问题：

| 问题 | 指导目标 |
|---|---|
| 前端整体如何分层 | 明确页面、组件、API、状态、权限、工具函数的职责边界 |
| 采购方与供应商门户如何隔离 | 通过路由、菜单、权限、数据上下文与接口约束实现隔离 |
| 页面如何保持统一体验 | 统一列表页、详情页、表单页、单据页、弹窗、审批与日志展示规范 |
| 如何对接后端接口 | 遵循 `/api/v1`、统一响应结构、错误码、分页、幂等、鉴权规范 |
| 如何降低维护成本 | 统一目录、命名、状态字典、通用组件、请求封装与测试策略 |

## 2. 前端建设目标

### 2.1 业务目标

| 目标 | 说明 |
|---|---|
| 支撑采购全流程协同 | 覆盖供应商准入、询报价、订单、交付、质量、对账、发票、付款等流程 |
| 支撑供应商自助操作 | 供应商可通过门户完成报价、接单、发货、整改、对账确认、资料维护 |
| 强化内外用户隔离 | 内部采购方用户与外部供应商用户在路由、菜单、数据、操作上严格隔离 |
| 提升单据处理效率 | 通过统一单据页面、批量操作、状态提示、待办提醒降低操作成本 |
| 保证过程可追溯 | 页面展示状态轨迹、审批记录、操作日志、附件版本、消息通知结果 |

### 2.2 技术目标

| 目标 | 说明 |
|---|---|
| 技术栈统一 | 使用 Vue 3.4+、Element Plus 2.4+、Vite 5.0+、Pinia、Vue Router 4、Axios |
| 类型与结构清晰 | 推荐使用 TypeScript，按模块维护 API 类型、查询参数、表单模型与响应模型 |
| 前后端契约稳定 | 严格适配后端统一响应、错误码、分页、权限、字典和状态机规则 |
| 权限前后端一致 | 前端做体验控制，后端做强制校验，前端不得假设隐藏按钮等于安全 |
| 可扩展可复用 | 抽象通用列表、表单、详情、附件、状态标签、操作日志等组件 |

## 4. 技术栈规范

| 类别 | 推荐技术 | 使用要求 |
|---|---|---|
| 框架 | Vue 3.4+ | 统一使用 Composition API 与 `<script setup>` |
| UI 组件 | Element Plus 2.4+ | 表单、表格、弹窗、分页、上传、消息提示保持统一风格 |
| 构建工具 | Vite 5.0+ | 使用环境变量区分 dev、test、uat、prod |
| 状态管理 | Pinia | 存储用户、权限、字典、布局配置、全局缓存 |
| 路由 | Vue Router 4 | 使用路由守卫控制登录、权限、门户隔离 |
| HTTP | Axios | 封装统一请求、响应、错误、重试、取消请求 |
| 工具库 | VueUse、Day.js、Lodash-es | 优先按需引入，避免不必要体积膨胀 |
| 类型系统 | TypeScript | 推荐所有新增模块使用明确接口类型 |

### 5.2 目录职责

| 目录 | 职责 | 禁止事项 |
|---|---|---|
| `api` | 按业务模块封装接口方法、请求类型、响应类型 | 页面中直接写 URL |
| `components/common` | 与业务无关的通用组件 | 混入业务权限或业务状态 |
| `components/business` | 跨页面复用的业务组件 | 与单个页面强绑定 |
| `composables` | 复用组合逻辑，如表格、字典、权限、上传 | 写大型业务流程编排 |
| `constants` | 常量、枚举、状态、正则、配置键 | 在页面散落魔法数字 |
| `directives` | 权限、复制、懒加载、防重复点击等指令 | 承载复杂业务判断 |
| `layouts` | 后台布局、门户布局、登录布局 | 写具体业务页面逻辑 |
| `router` | 静态路由、动态路由、路由守卫 | 在页面内自行判断是否可访问 |
| `stores` | 用户、权限、字典、标签页、全局配置状态 | 存放一次性页面临时变量 |
| `views` | 业务页面 | 复用逻辑全部堆在页面文件中 |

## 6. 命名规范

### 6.1 文件命名

| 类型 | 命名规则 | 示例 |
|---|---|---|
| 页面组件 | PascalCase | `PurchaseOrderList.vue`、`SupplierProfile.vue` |
| 通用组件 | PascalCase | `BaseTable.vue`、`FileUploader.vue` |
| 组合函数 | camelCase，以 `use` 开头 | `useTable.ts`、`usePermission.ts` |
| API 文件 | kebab-case 或模块名 | `purchase-order.ts`、`supplier.ts` |
| 类型文件 | 模块名 + `.types.ts` | `order.types.ts` |
| 常量文件 | 模块名 + `.constants.ts` | `order.constants.ts` |

### 6.2 变量命名

| 场景 | 命名规则 | 示例 |
|---|---|---|
| 列表数据 | `xxxList` | `orderList` |
| 查询参数 | `xxxQuery` | `orderQuery` |
| 表单模型 | `xxxForm` | `supplierForm` |
| 详情数据 | `xxxDetail` | `invoiceDetail` |
| 加载状态 | `xxxLoading` | `tableLoading` |
| 弹窗可见 | `xxxVisible` | `auditDialogVisible` |

## 7. 路由与门户隔离方案

### 7.1 路由分区

| 区域 | 路由前缀 | 面向用户 | 说明 |
|---|---|---|---|
| 登录页 | `/login` | 所有用户 | 登录、找回密码、供应商注册入口 |
| 采购方后台 | `/purchasing` | 内部用户 | 采购、质量、仓储、财务、系统管理员 |
| 供应商门户 | `/supplier` | 供应商用户 | 报价、接单、发货、质量整改、对账 |
| 系统管理 | `/purchasing/system` | 管理员 | 用户、角色、权限、字典、参数配置 |
| 错误页 | `/403`、`/404`、`/500` | 所有用户 | 权限不足、页面不存在、系统异常 |

### 7.2 路由守卫规则

| 检查项 | 规则 |
|---|---|
| Token 检查 | 非白名单路由必须存在有效 Token |
| 用户信息 | 刷新页面后必须重新拉取当前用户信息与权限 |
| 门户隔离 | 供应商用户不得进入 `/purchasing`，内部用户不得误入供应商工作台 |
| 权限检查 | 菜单路由必须匹配用户权限码或后端返回的路由权限 |
| 动态标题 | 根据路由 meta 设置页面标题与面包屑 |
| 异常跳转 | 401 跳登录，403 跳无权限页，404 跳不存在页 |

### 7.3 路由 Meta 建议

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 页面标题 |
| `permission` | string | 页面访问权限码 |
| `userType` | string | `internal`、`supplier` 或 `all` |
| `hidden` | boolean | 是否隐藏菜单 |
| `keepAlive` | boolean | 是否缓存页面 |
| `breadcrumb` | boolean | 是否显示面包屑 |
| `activeMenu` | string | 详情页对应的激活菜单 |

## 8. 布局设计规范

### 8.1 采购方后台布局

采购方后台应突出管理效率、批量处理、审批控制和异常预警，推荐布局包括：顶部栏、侧边菜单、面包屑、标签页、内容区、全局待办入口、用户菜单。

| 区域 | 内容 |
|---|---|
| 顶部栏 | 系统名称、折叠菜单、全局搜索、消息、待办、用户信息 |
| 侧边菜单 | 供应商、寻源、订单、交付、质量、结算、系统管理 |
| 内容区 | 列表、详情、表单、看板、流程处理页面 |
| 标签页 | 支持多页面切换，刷新、关闭、关闭其他 |
| 用户菜单 | 个人信息、修改密码、退出登录 |

### 8.2 供应商门户布局

供应商门户应突出待办、订单响应、交付进度、质量整改、对账状态和资料维护，减少复杂管理配置入口。

| 区域 | 内容 |
|---|---|
| 工作台 | 待接单、待发货、待整改、待对账、资质到期提醒 |
| 订单中心 | 订单确认、拒单、交期反馈、变更确认 |
| 发货中心 | ASN 创建、送货单打印、标签打印、收货差异 |
| 质量中心 | NCR、8D、整改附件、申诉 |
| 财务中心 | 对账确认、发票上传、付款进度 |
| 资料中心 | 企业资料、联系人、资质证书 |

## 9. 页面设计规范

### 9.1 列表页标准结构

所有业务列表页建议采用统一结构：查询区、操作区、表格区、分页区、批量操作区。

| 区域 | 设计要求 |
|---|---|
| 查询区 | 常用条件默认展开，高级条件可折叠，支持重置 |
| 操作区 | 新增、导入、导出、批量处理、刷新、列设置 |
| 表格区 | 状态标签、金额右对齐、日期统一格式、操作列固定右侧 |
| 分页区 | 默认页码、每页条数、总数，切换分页自动查询 |
| 批量区 | 多选后显示批量按钮，操作前二次确认 |

### 9.2 详情页标准结构

| 区域 | 内容 |
|---|---|
| 单据头 | 单号、状态、供应商、组织、金额、创建人、创建时间 |
| 基础信息 | 业务主字段，按分组展示 |
| 明细信息 | 订单明细、发货明细、收货明细、对账明细等 |
| 附件信息 | 上传文件、下载、预览、版本记录 |
| 操作日志 | 操作人、动作、前状态、后状态、时间、备注 |
| 审批记录 | 审批节点、审批人、审批意见、审批时间 |

### 9.3 表单页标准结构

| 规则 | 说明 |
|---|---|
| 表单分组 | 基础信息、联系人、财务信息、资质信息等按业务分组 |
| 必填标识 | 必填项必须明确展示，并与后端校验一致 |
| 字段联动 | 供应商、物料、订单选择后自动带出相关字段 |
| 金额数量 | 输入限制小数位，提交前保持数值类型一致 |
| 提交防重 | 提交按钮 loading，关键接口配合幂等 Token 或业务唯一键 |
| 离开提醒 | 未保存表单离开页面时提示用户确认 |

### 9.4 弹窗使用规则

| 场景 | 推荐方式 |
|---|---|
| 简单确认 | 使用确认弹窗 |
| 简单编辑 | 使用中等宽度表单弹窗 |
| 复杂单据 | 使用独立页面或抽屉，不建议塞入弹窗 |
| 审批意见 | 使用弹窗，包含意见、附件、下一节点 |
| 状态变更 | 使用确认弹窗并展示影响范围 |

## 11. API 对接规范

### 11.1 请求路径

前端接口必须遵循后端 `/api/v1` 版本前缀和 REST 资源风格。

| 业务 | 路径示例 |
|---|---|
| 供应商 | `/api/v1/suppliers` |
| 采购订单 | `/api/v1/purchase-orders` |
| 订单明细 | `/api/v1/purchase-orders/{id}/details` |
| 订单确认 | `/api/v1/purchase-orders/{id}/confirm` |
| ASN | `/api/v1/delivery-notices` |
| 质量异常 | `/api/v1/quality-issues` |
| 对账单 | `/api/v1/reconciliations` |

### 11.2 统一响应处理

前端请求层应统一处理以下响应格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": "2026-05-21 10:00:00",
  "traceId": "9f7c2a..."
}
```

处理规则：

| 场景 | 处理方式 |
|---|---|
| `code = 200` | 返回 `data` 给业务页面 |
| `400xx` | 展示参数或业务输入错误，必要时定位字段 |
| `401xx` | 清理登录状态并跳转登录页 |
| `403xx` | 提示无权限或跳转 403 页面 |
| `409xx` | 展示状态冲突、重复提交、版本冲突提示 |
| `500xx` | 展示系统异常提示，保留 `traceId` 便于排查 |

### 11.3 分页参数规范

| 参数 | 说明 |
|---|---|
| `pageNum` | 当前页码，从 1 开始 |
| `pageSize` | 每页条数 |
| `sortField` | 排序字段，必须使用后端允许字段 |
| `sortOrder` | `asc` 或 `desc` |

分页响应字段：

| 字段 | 说明 |
|---|---|
| `records` | 当前页数据 |
| `total` | 总条数 |
| `pageNum` | 当前页码 |
| `pageSize` | 每页条数 |
| `pages` | 总页数 |

### 11.4 请求封装要求

| 能力 | 要求 |
|---|---|
| Token 注入 | 自动添加 `Authorization: Bearer {token}` |
| 超时控制 | 设置统一超时时间，导入导出可单独配置 |
| 重复请求 | 查询类可取消上一次未完成请求 |
| 错误提示 | 统一提示，页面避免重复弹错 |
| Trace 展示 | 系统异常可展示或复制 `traceId` |
| 文件下载 | 从响应头解析文件名，校验权限失败时按 JSON 错误处理 |

## 12. 权限控制方案

### 12.1 权限层级

| 层级 | 前端控制方式 | 说明 |
|---|---|---|
| 路由权限 | 路由守卫、动态路由 | 无权限页面不可进入 |
| 菜单权限 | 后端权限树生成菜单 | 无权限菜单不展示 |
| 按钮权限 | 指令或组件属性控制 | 新增、编辑、删除、审核、导出等 |
| 数据权限 | 页面只展示后端返回数据 | 不在前端拼接越权条件 |
| 字段权限 | 敏感字段脱敏或隐藏 | 银行账号、税号、手机号等 |

### 12.2 权限码命名建议

| 模块 | 权限码示例 |
|---|---|
| 供应商 | `supplier:view`、`supplier:create`、`supplier:audit`、`supplier:export` |
| 订单 | `order:view`、`order:confirm`、`order:change`、`order:export` |
| 发货 | `delivery:view`、`delivery:create`、`delivery:print` |
| 质量 | `quality:view`、`quality:inspect`、`quality:ncr:audit` |
| 结算 | `settlement:view`、`settlement:confirm`、`settlement:invoice` |
| 系统 | `system:user`、`system:role`、`system:dict` |

### 12.3 供应商数据隔离

供应商用户的 `supplier_id` 必须来自登录用户上下文。前端不得允许供应商用户手工切换或传入其他供应商 ID。供应商门户页面如需展示供应商信息，应调用“当前供应商”相关接口，而不是复用采购方后台的任意供应商查询接口。

| 场景 | 前端要求 |
|---|---|
| 订单查询 | 不展示供应商筛选项或固定为当前供应商 |
| ASN 创建 | 只能从当前供应商可发货订单中选择 |
| 质量整改 | 只能处理当前供应商相关 NCR |
| 对账确认 | 只能查看当前供应商对账单 |
| 附件下载 | 下载前由后端校验权限，前端不暴露真实对象存储路径 |

## 18. 安全规范

### 18.1 Token 安全

| 规则 | 说明 |
|---|---|
| 请求头传输 | 使用 `Authorization: Bearer {token}` |
| 过期处理 | 过期后跳转登录或触发刷新令牌逻辑 |

| 第四阶段 | 完善附件、导入导出、消息待办、操作日志、看板 | 体验与追溯能力完善 |
| 第五阶段 | 性能优化、安全加固、测试补齐、生产配置 | 达到上线要求 |

## 27. 总结

前端建设应围绕“统一体验、权限清晰、接口稳定、状态可控、数据安全、可持续扩展”展开。采购方后台重点保障管理效率和业务管控，供应商门户重点保障协同效率和自助体验。所有页面、组件、接口、状态、权限与文件能力都应遵循统一规则，避免模块各自为政，为后续模块扩展、服务拆分、移动端适配和多租户演进打下基础。
